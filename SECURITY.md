# Security Policy

## Supported versions

Only the latest tagged release receives security fixes. There are no
long-term-support branches.

## Reporting a vulnerability

Report security issues privately via GitHub's "Report a vulnerability" feature
on the **Security** tab, or email **jtstothard@gmail.com** with `[security]` in
the subject line.

Do **not** open a public issue for security problems.

Please include:
- A description of the issue and its potential impact
- Steps to reproduce, including a minimal config
- The affected version (from `pip show hermes-tiered-memory`)

You will receive an acknowledgement within 72 hours. Valid reports will be
fixed in a patch release and credited in the changelog unless you prefer
otherwise.

## Security model (v1.0.0)

### Secret boundary

`hermes-tiered-memory` never creates, reads, persists, or exposes cloud
credentials. The Hindsight API key (when `auth_mode: api_key`) lives in the
active Hermes profile's secret configuration and is passed only to the L2 HTTP
adapter's authorization header. It does not appear in:
- The protected endpoint configuration file
- Output generated by `hermes-tiered-memory provision`
- Output generated by `hermes-tiered-memory doctor`
- Logs or error messages

### Protected configuration

The endpoint document is canonical compact JSON with a detached Ed25519
signature covering `hermes-tiered-memory/config/v1\0 || canonical-bytes`. The
loader rejects unknown keys, missing/invalid signatures, non-canonical bytes,
expired or not-yet-valid documents, and sequence rollback. Accepted sequence
and digest state is persisted separately to prevent silent rollback.

### Authentication modes

`memory.tiered.hindsight.auth_mode` accepts only:
- `api_key` — requires a non-empty credential in the active profile's secrets
- `none` — requires that credential to be absent (self-hosted, no-auth endpoint)

Mismatched combinations fail closed during initialization.

### File protection

`provision` creates all output files with mode `0600`, refuses overwrites
unless `--force` is explicit, and uses no-follow file creation. The Ed25519
private key is signing material — keep it offline or in an approved secret
store; never commit it.

### Transport

The protected configuration schema requires HTTPS. TLS verification is enabled
by default. Disabling TLS verification together with a configured CA bundle is
rejected.

For the full cryptographic and implementation detail, see
[docs/security.md](docs/security.md).

## Out of scope

- The L1 and L2 adapters are internal implementation details and not a public
  extension point.
- The protected-config wire format and signature domain separator are not
  versioned API guarantees in v1.0.0.
- `doctor` performs read-only health checks; it does not mutate live Hermes
  configuration.
